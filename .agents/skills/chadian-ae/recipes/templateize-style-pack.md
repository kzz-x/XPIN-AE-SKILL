# Recipe｜做成视觉系统模板包

适用：用户希望把现有 AEP / 已完成镜头 / 一组同风格组件整理成可长期复用的人机共用模板。

包括但不限于：
- “做成模板”
- “整理成模板”
- “模板化”
- “做成模板库里的东西”
- “沉淀到模板库”
- “拆成独立组件”
- “做成一整套视觉系统”
- “把这个 AEP 做成人和 AI 都能直接用的模板”

## P0｜先保护原件
模板化不是“在原工程里整理”。

正式写入前必须：
1. 确认源 AEP / 源素材位置；
2. 建立可靠恢复点；
3. 创建独立模板化工作副本；
4. 后续重命名、整理、拆组件、删冗余、Relink、依赖收集等只作用于副本；
5. 不移动、不覆盖、不删除用户本地原 AEP 与原素材；
6. 工具不能可靠复制 / 备份时，不进行高风险结构写入。

## 执行目标
优先把资产整理成：
`视觉系统包 → 完整套装 → 场景模板 / 独立组件 → 公共素材 / 依赖 / 预览 / 说明`

完整套装是唯一设计母体。独立组件和场景从完整套装派生，不分别长期维护。

## AE 内部硬规则
- 模板型 AEP 项目面板优先：`00_开始这里 / 01_主输出 / 02_编辑区 / 03_替换槽位 / 04_功能模块 / 05_素材 / 90_参考 / 99_核心`。
- **控制器属于合成内部**：每个主要可编辑合成时间线最上方放自己的控制 Null；不要额外用项目面板“控制文件夹”替代这一入口。
- 高频替换内容 SLOT 化。
- 底层 Rig / 表达式 / 材质等进入核心区域，正常调用默认不动。
- 人类可见命名中文优先。

## 依赖
必须盘点插件、字体、脚本、预设、LUT、Codec、3D 模型 / HDRI / 贴图、外部媒体 / 数据、Adobe 版本、Dynamic Link / Media Encoder、GPU 等可能脱机项。

可合法分发的依赖可随包提供；商业 / 受限依赖只提供版本、官方来源、安装说明和缺失影响。

缺依赖时先提醒，不得静默替换。

## AI 自主依赖收集

模板化任务默认**不用 AE 原生“收集文件”**。优先由 AI / MCP 读取当前模板副本真实引用，再通过文件系统复制到模板包，最后补扫环境依赖并做外部路径残留检查。

标准流程：

`工程真实引用 → 复制素材到模板包 → 补扫环境依赖 → 分类打包 / 记录 → 外部路径残留检查`

### 第一轮｜工程真实引用
只沿当前模板 / 资产根合成的必要依赖读取并收集：
- 图片 / 视频 / 音频 / 序列帧；
- JSON / CSV / 外部数据；
- LUT / FFX / 自制脚本；
- 三维模型 / HDRI / 贴图；
- 其他被当前模板真实引用的文件。

要求：
- 只复制，不移动、不删除、不覆盖原文件；
- 复制进模板包对应目录后，再让模板副本指向包内副本；
- 不为了“保险”扫描或复制整个磁盘 / 素材库 / Program Files；
- 只收当前模板真实需要的最小必要集合。

### 第二轮｜环境依赖补全
补扫 AE Footage 不一定直接管理的依赖：
- 字体与特殊字重；
- AE / PR 第三方插件；
- 单文件 `.aex` 与其可能的伴随 DLL / 资源目录；
- CEP / UXP；
- JSX / JSXBIN / 第三方脚本；
- FFX / LUT / ICC / OCIO；
- Codec；
- 3D Renderer；
- Dynamic Link / Media Encoder / Adobe 版本；
- GPU / CUDA 或其他特殊运行环境。

### 第三轮｜分类处理

**A｜自动复制打包**
- 当前模板真实引用的图片 / 视频 / 音频 / 序列帧；
- JSON / CSV / 数据；
- LUT / FFX；
- 自制脚本；
- 三维模型 / HDRI / 贴图；
- 许可证允许随包分发的字体；
- 经确认“单文件自包含 + 无额外授权 / 伴随文件 + 允许分发”的 `.aex`。

**B｜检查后再复制**
- 字体；
- 单个 `.aex`；
- CEP / UXP；
- 第三方脚本。

若插件存在 DLL、资源目录、注册表 / 服务、安装器或授权系统，不得只复制一个 `.aex` 冒充完整依赖；应复制合法且必要的整套文件，或转为“仅记录”。

**C｜只记录，不打包**
- Red Giant / Maxon、Sapphire 等安装器 + 授权体系插件；
- Adobe 自带组件；
- 许可不允许再分发的商业字体 / 素材 / 插件；
- 无法确认自包含性或许可状态的依赖。

仅记录：名称、版本、原路径、官方来源、安装方法、是否必须、缺失影响、替代方案。

### 第四轮｜外部路径残留检查
收集后检查模板副本是否仍依赖：
- 原项目目录；
- 原素材目录；
- NAS 原路径；
- 桌面 / 下载 / 临时目录；
- 原插件 / 字体 / 脚本绝对路径；
- 其他机器特有路径。

能安全重定向到模板包内副本的就重定向；不能自包含的必须进入 `依赖说明.md`。

### 依赖清单
每项至少记录：
- 名称 / 类型；
- 原始路径；
- 模板包内路径；
- 版本；
- 是否必须；
- 是否已复制；
- 是否允许分发；
- 是否需要安装；
- 是否可能存在伴随文件；
- 缺失影响。

**不确定是否合法、是否必要、是否自包含时，宁可记录，不要暴力复制。**

## 轻量预览输出

模板化任务允许自动生成短预览视频，但这是**低成本预览例外**，不是完整成片渲染授权。

默认：
- 完整套装：只做约 5–10 秒代表性整体预览；
- 场景模板：约 3–8 秒；
- 独立组件：约 2–5 秒；
- 优先 720p / 普通 H.264 或等价轻量设置；
- 只渲染代表性时间段，不因原合成很长就全长输出；
- 本轮没改、已有可用预览的内容不重复渲染；
- 遇到重插件 / 3D / 高成本效果时，优先缩短、降分辨率，必要时静帧替代；
- 预览不得成为模板化流程的主要耗时项。

正式高质量成片、完整长视频和最终交付渲染仍需用户明确授权。

## 发布门禁
模板完成后先进入待审核，不自动覆盖旧正式模板。
正式发布版只读；生产使用必须复制到工作区。
已有项目中的模板副本不自动随母版升级。

## 完成回报
保持简短，至少说明：
1. 本次操作的是哪个副本，源工程是否保持未改；
2. 完整套装 / 场景 / 独立组件整理结果；
3. 依赖与缺失项；
4. 主要 SLOT / CTRL 使用入口；
5. 还未达到发布标准的项目。
