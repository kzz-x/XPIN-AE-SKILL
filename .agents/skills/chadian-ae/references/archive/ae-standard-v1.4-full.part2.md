简单工程可以合并，但逻辑仍应保持分类。

## 全局样式控制

例如：

```text
[颜色] 背景
[颜色] 主文字
[颜色] 次文字
[颜色] 强调色_A
[颜色] 强调色_B
[颜色] 警告色
[颜色] 面板底色
[颜色] 描边色

[线条] 细线
[线条] 标准线
[线条] 强调线

[圆角] 小
[圆角] 中
[圆角] 大
[圆角] 胶囊

[透明度] 次级元素
[透明度] 辅助线
[透明度] 背景元素
```

注意：

**“统一控制”不等于“全部一样”。**

必须建立不同等级，例如：

```text
描边：
细线 / 标准线 / 强调线

圆角：
S / M / L / Pill

文字：
标题 / 副标题 / 正文 / 数据 / 标签 / 注释
```

不同元素调用不同 Token。

# 04｜文字系统

禁止所有文字只使用一种字体和一个粗细。

至少建立：

```text
T1｜主标题
T2｜副标题
T3｜正文
T4｜数据数字
T5｜工业标签
T6｜辅助注释
```

每类文字独立定义：

- 字体
- 字重
- 字号
- 行距
- 字距
- 对齐方式
- 颜色
- 透明度

例如视觉逻辑可以是：

```text
主标题 → 高字重 / 压缩体
正文 → 正常无衬线
数据 → DIN / 数字字体
参数 → Mono 等宽字体
工业标签 → 中等字重 + 较大字距
```

字体尽量通过**文字样式参考层 / 样式系统**统一管理，而不是每层独立设置。

如果指定字体不存在：

1. 不得导致脚本报错停止。
2. 自动使用备用字体。
3. 在工程中留下“字体替换提示”。

# 05｜颜色 / 描边 / 圆角 / 几何参数

所有高频视觉属性尽量绑定控制系统：

- Fill Color
- Stroke Color
- Stroke Width
- Opacity
- Rectangle Roundness
- UI 面板透明度
- 阴影强度
- Glow 强度
- 模糊量
- 间距
- Padding
- 元素尺寸
- 图标尺寸

但不要把每一个微小参数都暴露出来。

判断原则：

**以后可能经常修改的 → 控制层。**

**只属于某个局部造型的 → 保留在局部图层。**

# 06｜动画时间必须 Marker 化

动画不能只靠写死的：

```text
0秒
0.5秒
1.3秒
```

主合成建立：

```text
CTRL_动画
```

通过 Marker 定义主要阶段，例如：

```text
[入场开始]
[入场结束]
[稳定]
[出场开始]
[出场结束]
```

或者：

```text
IN
HOLD
OUT
END
```

动画通过 Marker 时间计算。

这样用户只需要拖 Marker，就能改变：

- 动画出现时间
- 入场长度
- 停留长度
- 出场开始
- 出场长度

不用重新修改几十个关键帧。

# 07｜元素级动画控制

不同元素除了总 Marker，还应该允许拥有自己的局部控制。

例如：

```text
[动画] 位移距离
[动画] 缩放幅度
[动画] 旋转幅度
[动画] 延迟
[动画] 错开间隔
[动画] 弹性
[动画] Overshoot
[动画] 模糊强度
[动画] 缓动强度
[动画] 曲线类型
```

禁止把所有动画都做成：

```text
Opacity 0→100
Scale 80→100
```

必须根据元素类型设计动画。

例如：

```text
窗口 → 展开 / 裁切 / 弹窗
数据 → 计数 / 扫描 / 增长
机械结构 → 位移 / 锁定 / 装配
标签 → Draw On / Slide
电脑界面 → 系统级窗口动画
鼠标 → Position + Click反馈
工业模块 → 卡扣 / 推入 / 对齐
图标 → 路径绘制 / 形状变换 / 状态切换
```

# 08｜动效关键帧与运动曲线规范

所有具有明显运动、缩放、旋转、透明度变化或路径变化的动效，都必须具备合适的关键帧和运动曲线。

禁止：

- 只有起点和终点、完全没有缓动的线性动画。
- 所有元素使用同一种速度曲线。
- 机械结构使用过度弹性的卡通曲线。
- UI 界面使用不符合系统逻辑的夸张回弹。
- 复杂动作只改变 Position，不考虑 Scale、Opacity、Blur、Mask 或路径变化。
- 关键帧时间间隔不符合动作重量和节奏。

应根据元素属性选择合适的曲线：

```text
UI 界面 → Ease In / Ease Out，节奏干净
机械结构 → 较短缓入缓出，必要时加入轻微锁定感
弹性物体 → 合理 Overshoot / Bounce
数据增长 → 平滑 Ease，避免突然跳变
扫描线 → 匀速或轻微加减速
镜头推进 → 平滑缓入缓出
按钮点击 → 快速缩放反馈 + 回弹
标签出现 → 快速进入 + 短暂稳定
```

关键帧必须经过 Graph Editor 或等效曲线逻辑检查。

推荐使用：

- Easy Ease
- Bezier 曲线
- Speed Graph
- Value Graph
- 自定义缓动函数
- 适度的 Overshoot
- 适度的 Motion Blur

但不得为了“有曲线”而滥用弹性或回弹。

动画验收标准：

- 动作开始和结束自然。
- 不出现突然刹停。
- 不出现无意义抖动。
- 不出现元素互相穿插。
- 不出现速度忽快忽慢但没有设计意图。
- 不同元素之间具有合理的延迟和层次。
- 动画曲线与元素材质、重量、功能相匹配。

---

# 09｜复杂动画标准化

复杂动画推荐将内部动作制作成标准时间段，例如：

```text
0–1 秒 = 一个完整入场动作
```

外部再通过：

- Marker
- Time Remap
- Precomp
- 时间伸缩
- 动画控制器

控制实际速度。

这样复杂 Shape Path、Mask、逐字动画不需要每次重做。

复杂动画应尽量拆分为：

```text
准备
启动
主体运动
减速
锁定 / 停留
结束
```

每个阶段都应有明确的关键帧和曲线逻辑。

# 10｜图标与复杂元素来源规范

当某些图标、专业符号、机械结构、地图、设备轮廓或复杂 UI 元素难以高质量绘制时，可以调用网上的开源库或公开素材，但必须遵守以下规则：

- 优先使用开源、免费、授权清晰的素材库。
- 优先选择 SVG、AI、EPS、JSON 或其他可编辑矢量格式。
- SVG 原生导入能力可能随 AE 版本 / Beta 状态变化；当前环境不支持时，应转为 AI / Shape / 可编辑矢量流程，不得因此中断。
- 不要随意截图或直接复制来源不明的图片。
- 不要使用明显带有版权风险的品牌 Logo、商业图标或付费素材。
- 不要把不同风格、不同线宽、不同圆角体系的图标直接混用。
- 使用前必须检查授权类型和商业使用限制。
- 需要记录素材来源、作者、许可证和下载地址。
- 如果许可证要求署名，应在工程注释或项目说明中保留署名信息。
- 如果素材不允许修改、再分发或商业使用，不得用于对应项目。
- 下载后应尽量转为可编辑的 Shape、矢量预合成或独立素材槽。
- 不得依赖在线链接实时加载素材，避免链接失效导致工程无法打开。
- 如果无法确认授权，应放弃使用，改用 AE 原生图形或寻找授权明确的替代品。

推荐来源类型：

```text
开源 SVG 图标库
开源插画库
公开授权的工业符号库
Creative Commons 素材
允许商业使用的矢量资源
```

使用开源素材后，应根据项目视觉系统进行统一处理：

- 统一线宽。
- 统一圆角。
- 统一颜色。
- 统一视觉比例。
- 统一描边端点和连接方式。
- 统一阴影、透明度和发光效果。
- 必要时重新整理路径结构。

禁止直接把来源素材原样堆进工程，导致视觉风格不一致。

## 09A｜外部素材获取 / 下载 / 导入 / 占位规范

如果镜头明显需要真实图片、视频、产品图、工业设备、人物、纹理、地图、品牌资产或复杂 3D 素材，AI **应主动判断是否需要外部素材**，而不是一律退化成 Shape 占位。

当运行环境具备联网、浏览、下载或素材生成能力时，可以：

1. 搜索合适素材。
2. 优先官方来源、原作者来源、开源仓库或授权清晰素材库。
3. 下载到项目本地素材目录。
4. 记录来源、许可证、文件名和用途。
5. 由 JSX 导入本地文件，不让 AE 工程依赖在线 URL。
6. 建立可替换的素材槽并保留裁切、圆角、Matte、色彩处理与动画。

### 素材搜索优先级

```text
品牌 / 产品 → 官方网站、官方媒体资源、官方 Press Kit
图标 / UI → 开源 SVG / Icon Library
真实场景 → 授权清晰的图库 / 视频库
工业 / 机械 → 官方产品图、CAD / 3D 公开资源、授权素材
Logo → 官方品牌资源优先
纹理 / HDRI / 3D → 许可证明确的专业资源库
```

**公开可访问不等于可商用。** 无法确认授权时，不得把素材默认为最终商用资产。

### 如果 AI 无法直接获取素材

不得因此让整个 JSX 失败。应按以下顺序处理：

```text
能生成合理替代素材 → 先生成并导入
↓
不能生成但可以准确描述需求 → 建立高质量占位素材槽
↓
在工程 / 交付说明中列出用户需要提供的文件
```

占位不应该只是一个随便的灰色方块。应尽量保留最终素材的：

- 实际画幅比例。
- 裁切方式。
- 安全区。
- Mask / 圆角。
- 入场 / 出场动画。
- Track Matte。
- 色彩处理。
- 景深 / 模糊关系。

推荐命名：

```text
【待替换】产品正面.png
【待替换】焊接实拍.mp4
【待替换】工业机器人.glb
【待替换】人物照片.psd
```

这样用户后续替换素材时，不需要重做镜头。

### JSX 与下载职责分离

不要把“联网找素材”强行塞进 JSX。

更稳定的流程是：

```text
AI / Work / 外部工具先完成搜索与下载
↓
文件落到本地
↓
JSX 只负责导入、组织、处理和动画
```

如果本次交付无法提供素材文件，应让 JSX 创建清晰的占位槽，并在交付信息里准确告诉用户缺什么。

# 14｜为 AI 保留稳定 ID

**名字是给人看的，ID 是给 AI / 脚本看的。**

不要让后续修改脚本依赖：

```text
layer(7)
```

应该给重要图层 / 合成加入稳定标识。

例如 Layer Comment：

```text
AI_ID=computer_screen
ROLE=main_screen
TYPE=replaceable
```

或者：

```text
AI_ID=window_steel_01
```

以后 AI 修改时优先：

```text
查找 AI_ID
→ 确认对象
→ 修改
```

而不是：

```text
找到第17层
→ 修改
```

这样即使用户移动、插入、删除图层，脚本依然可靠。

# 17｜镜头系统

```text

[镜头] 景深

```

如果只是模拟摄影机推进，不必强行使用 AE 3D Camera。

只有真正需要：

- 景深
- 透视
- 多层空间
- 3D Parallax

时才建立 Camera。

镜头动画必须使用合理的缓入缓出和速度曲线，不能简单地线性推拉。

## 16A｜2.5D / 3D / Camera / Light / 3D Model

当二维层无法自然表达空间关系时，可以主动使用 AE 的空间能力。

适合使用：

```text
3D Layer
Camera
Light
Depth of Field
Parent / Null Camera Rig
多层 Z 空间
Parallax
阴影 / 材质选项
AE 支持的 3D Model
外部渲染好的 3D 序列 / PNG / EXR
```

典型适用镜头：

- 从屏幕内部拉到整台电脑。
- 多层 UI 空间展开。
- 产品信息层围绕设备形成空间关系。
- 芯片 / 手机 / 电脑 / 工业设备具有真实透视旋转。
- 需要景深、遮挡、空间层级和 Parallax 的镜头。

### 使用原则

- 能用二维父级 + Scale 模拟并达到效果时，不必强行 3D 化。
- 真正需要空间关系时，Camera 与物体动画分离。
- Camera 尽量绑定 NULL_镜头Rig，不直接堆大量难以编辑的 Camera 关键帧。
- 不要默认把所有 UI 卡片打开 3D。
- 不要为了“电影感”滥用 DOF、镜头晃动和大幅透视。
- 3D Model 优先考虑 GLB；需要依赖外部纹理的 GLTF / OBJ 时，要把依赖文件一起归档。
- 3D 模型层的相机景深 / Motion Blur 能力受 AE 当前实现限制时，可通过预合成后的 2D DOF / Blur / Motion Blur 等方式降级，不要假设所有 3D 模型都支持完整相机特性。

### 3D 模型边界

可以把 AE 支持的 3D 模型作为场景资产使用，并对 AE 暴露的整体属性进行控制。

但不要把 AE / JSX 当成 Blender、C4D 或 Houdini。以下任务默认不应承诺由 JSX 稳定完成：

- 复杂建模。
- Mesh 顶点级编辑。
- UV 展开。
- 骨骼 Rig。
- 复杂角色绑定。
- 高级材质节点搭建。
- 复杂动力学 / 流体 / 布料模拟。

如果镜头真正需要这些能力，应：

```text
外部 3D 工具完成
↓
输出 GLB / OBJ / 渲染序列 / EXR / PNG 等适合资产
↓
再由 AE / JSX 负责合成、镜头、信息层与后期
```

# 18｜表达式规范

表达式必须：

- 简短。
- 可阅读。
- 能复用。
- 有必要时写中文注释。
- 避免重复计算。
- 避免复杂递归。
- 避免大量逐帧扫描。
- 避免无意义 `sampleImage()`。
- 避免一层复制一大段完全相同代码。
- 不替代本应由关键帧和曲线完成的动画设计。

复杂逻辑示例应说明：

```javascript
// 根据「入场开始」和「入场结束」Marker
// 自动计算当前动画进度
```

表达式中对不存在对象必须尽量有容错。

如果表达式控制动画曲线，应明确说明：

```javascript
// 使用平滑缓入缓出
// 根据元素类型调整 Overshoot
// 避免在结束位置产生突兀跳变
```

## 17A｜不要遗漏 AE 原生高级动画能力

在合适场景下，AI 应主动考虑 AE 原生能力，而不是只会 Position / Scale / Opacity。
