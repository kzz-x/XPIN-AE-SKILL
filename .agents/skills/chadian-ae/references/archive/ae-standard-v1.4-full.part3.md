```

例如：

```text
逐字 / 逐词动画 → Text Animator，而不是拆几十个文字层
线条绘制 → Path + Trim Paths
窗口揭示 → Mask / Track Matte
重复模块 → Repeater / 预合成复用
复杂时间控制 → Precomp + Time Remap + Marker
统一后期质感 → Adjustment Layer
素材替换但保留模块逻辑 → Essential Properties / 素材槽
```

原则：**优先使用最符合 AE 工作方式的原生结构，而不是为了脚本好写，把所有效果都退化成基础图层。**

# 19｜AE26 中文版兼容

这是硬性要求。

JSX 操作 AE 属性时，尽量使用稳定的 **matchName**，不要依赖中文版 / 英文版属性名称。

例如优先使用：

```text
ADBE Transform Group
ADBE Position
ADBE Scale
ADBE Opacity

ADBE Slider Control
ADBE Color Control
ADBE Checkbox Control
ADBE Angle Control
ADBE Point Control
ADBE Layer Control
```

而不是依赖：

```text
"Transform"
"变换"
"Position"
"位置"
```

脚本显示给用户的名称可以全部中文，但底层访问尽量使用稳定标识。

# 20｜Effects / 第三方插件使用规范

AE 原生 Effects 与已安装的第三方插件都可以成为正常制作手段。

原则不是“禁止插件”，而是：

> **原生能高质量完成就优先原生；插件能明显提升质量、效率或实现原生难以达到的效果时，可以主动使用。**

### AE 原生 Effects

不要只使用 Fill / Blur 这种最基础效果。根据镜头需要，可以合理组合：

```text
Blur / Sharpen
Glow
Distort / Displacement
Noise / Grain
Color Correction
Keying
Transition
Channel / Matte
Generate
Stylize
Perspective
Time
Utility
```

效果应服务于视觉目标，不要为了复杂而堆效果。

### 第三方插件可以主动使用

例如项目本机已安装并且镜头确实适合时，可以使用诸如：

```text
Glow / Bloom 类
光效 / Lens Flare 类
粒子类
高级 Blur / Distortion 类
高级调色类
3D / Model 类
风格化 / Transition 类
```

具体插件品牌不是硬性要求，应以用户机器实际安装情况为准。

### 插件使用前必须检查

```text
1. 这个效果是否真的需要插件？
2. AE 原生是否已经足够？
3. 插件是否已安装？
4. JSX 是否能够稳定添加该 Effect？
5. 关键参数是否能通过 Property API / matchName 稳定访问？
6. 插件缺失时是否有原生降级方案？
7. 插件会不会显著降低性能或导致工程难以移交？
```

### 插件存在

可以使用，并：

- 给关键参数建立合理控制。
- 不要把插件几百个参数全部暴露。
- 在 Layer Comment 或项目说明中记录插件名 / 用途。
- 重要插件依赖建议建立 `DEPENDENCY=PluginName` 标记。

### 插件不存在

不得静默失败，也不得因此让整个 JSX 中断。

优先：

```text
有合理原生替代 → 自动降级，并告知用户
↓
没有合理替代 → 建立占位 / 保留效果入口
↓
明确告诉用户：建议安装哪个插件、用于什么效果
```

例如交付说明：

```text
【可选插件】Deep Glow：用于主标题高质量 Bloom。
当前未检测到，因此已自动使用 AE 原生 Glow 降级。
安装后可替换，工程其他部分不受影响。
```

不得声称某插件已安装，除非实际检测 / 调用成功。

缺少插件时只需要明确告诉用户“建议安装什么、用于什么、是否必须”。除非用户明确要求，不要擅自安装第三方插件或修改系统级插件环境。

如果插件只能够通过 UI 操作、参数没有稳定暴露给脚本，则不要假装可以完整自动化；应创建可控的基础结构，并把需要用户手动调整的步骤写清楚。

如果使用外部图标库或素材库，不应将其视为插件依赖。素材必须随项目保存或嵌入，并记录来源和许可证。

## 19A｜能力边界与人工接管

AI / JSX 不应为了“全自动”而承诺 AE 脚本 API 没有稳定开放的能力。

以下类型的任务应特别谨慎：

```text
Roto Brush / 高级智能抠像
部分自动 Tracking / Camera Solve 工作流
Content-Aware Fill
需要大量人工视觉判断的精细 Mask
第三方插件自定义面板内部功能
复杂 3D Rig / Mesh / Simulation
需要人工逐帧修正的画面处理
```

如果脚本无法稳定完成：

1. 先把前后工程结构搭好。
2. 创建明确命名的待处理层 / 预合成。
3. 保留前后动画与控制关系。
4. 告诉用户只需要手动完成哪一步。
5. 不因为一个无法自动化步骤，放弃整个工程自动搭建。

推荐标记：

```text
【需手动】Roto Brush 人物抠像
【需手动】3D Camera Tracker 求解
【需插件】高级粒子效果
【待素材】产品 45° 官方 PNG
```

# 21｜Essential Graphics / MOGRT

不要“能暴露的全部暴露”。

只暴露真正需要修改的参数，例如：

```text
文字
主颜色
图片
Logo
尺寸
开关
少量动画参数
```

大量插件参数、复杂表达式参数全部暴露到 PR，会增加模板复杂度和性能负担。

动画曲线、缓动类型和关键帧结构应尽量保留在工程内部，除非用户明确需要在 MOGRT 中调整。

# 22｜脚本生成规范

生成 JSX 时必须：

```javascript
app.beginUndoGroup("创建 XXX 工程");
```

执行结束：

```javascript
app.endUndoGroup();
```

同时应做到：

- 使用 try / catch。
- 错误信息说明是哪一步失败。
- 不随意删除用户现有工程内容。
- 不覆盖同名合成而不提示。
- 不依赖固定 Layer Index。
- 创建完成后自动定位主合成。
- 能重复执行时尽可能避免产生垃圾重复层。
- 修改现有工程时只修改目标对象。
- 创建外部素材时记录来源和许可证。
- 如果素材下载或导入失败，提供明确的降级方案。
- 不因单个图标或素材导入失败而导致整个工程无法创建。
- 如果使用了第三方插件，记录插件依赖与降级状态。
- 如果存在待替换素材、待安装插件或需手动处理步骤，在交付时统一列出。
- JSX 不负责运行时联网寻找素材；素材应优先在脚本执行前落到本地。

## 22A｜AEmcp / 直接 AE Agent 执行规范

当 Agent 不是生成 JSX，而是通过 MCP / 直接工具控制 After Effects 时：

- 先读取，再修改；不得盲写。
- 优先读取当前活动 Project、主合成、目标合成及目标图层的真实状态。
- 对重要对象优先检查 `AI_ID`、名称、Comment、Role、父级和预合成关系。
- 修改前记录将要影响的对象范围。
- 不随意新建第二套控制系统、重复合成或重复素材槽。
- 不因为 MCP 可以逐步点击 UI，就退化成低质量手工堆层。工程结构仍必须符合本规范。
- 对重复、批量、确定性很强的操作，可以转交 JSX / 脚本完成，再由 MCP 做结果检查。
- 如果 MCP 无法稳定访问某项能力，不应假装已经完成；应说明限制，并使用脚本、占位或人工接管路线。
- 每次写入后检查是否出现表达式错误、素材丢失、图层重复、关键帧被覆盖或用户手工修改被破坏。
- 默认禁止在每次制作 / 修改 / 调试完成后自动渲染完整成片；只执行阶段 4 的关键帧静帧验收。

# 23｜项目默认参数

没有特殊要求时建议：

```text
1920 × 1080
Square Pixel
25 / 30 fps 根据项目
时长按内容决定
```

不要默认生成 4K / 8K。

需要后期超大比例放大时，再明确使用高分辨率合成。

# 24｜安全框与构图

主要信息必须留在安全区域。

不要自动把内容撑满整个画面。

至少考虑：

```text
标题安全区
字幕区域
画面边缘呼吸空间
后期裁切空间
镜头运动空间
```

尤其 UI / 工业信息图，应避免卡片、标签贴边。

# 26｜关键位置写注释

容易误解的位置可以使用：

- Layer Comment
- Marker Comment
- Guide Layer
- 隐藏说明文字层

例如：

```text
【说明】只替换本层素材
【说明】拖动 Marker 修改入场时长

# 27｜性能规范

避免：

- 数百层无意义 Shape。
- 每层大量重复表达式。
- 大量实时 Blur。
- 大面积高采样 Glow。
- 无必要开启所有 Motion Blur。
- 无必要 3D 化所有元素。
- 巨量路径点。
- 每帧执行复杂字符串查找。
- 导入大量未使用的开源素材。
- 使用高分辨率位图替代本可使用的矢量图标。

需要视觉复杂度时优先：

```text
合理预合成
共享控制
模块复用
矢量素材
```

而不是单纯堆图层。

# 28｜AI 修改现有工程时的原则

以后 AI 不应该“重新生成整个工程”来修改一个小地方。

优先：

```text
识别目标 Comp
↓
通过 AI_ID / 名称找到目标
↓
只修改相关属性
↓
保留用户已经做过的人工修改
```

例如用户说：

> 把钢板窗口变大一点。

AI 应只修改：

```text
窗口_钢板
```

不得重新创建全部窗口。

如果用户要求替换图标：

```text
查找 AI_ID
↓
确认图标素材槽
↓
检查新素材授权
↓
替换路径或素材
↓
保留原有动画、父级和控制关系
```

```

# 30｜最终验收标准

AI 在交付 AE 工程 / JSX 前必须检查：

### 工程

- 主合成存在。
- Precomp 层级合理。
- 图层有清晰命名。
- 没有大量默认名称。
- 没有丢失表达式。
- 外部素材已归档或嵌入。
- 开源素材有来源和许可证记录。
- 真实素材、矢量、Shape、3D、Effects 的选择符合镜头需求，没有为了方便脚本而低质量手绘。
- 如果使用占位素材，待替换位置清晰且替换不会破坏动画。

### 视觉

- 色彩系统有层级。
- 字体有层级。
- 描边有粗细区分。
- 圆角有尺寸区分。
- 留白合理。
- 图标风格统一。
- 复杂元素没有低质量随意手绘。
- 外部素材已经经过必要的风格统一。
- 没有为了展示能力而滥用 Glow、粒子、3D、Camera、Light 或插件。

### 控制

- 颜色可统一调整。
- 字体体系可统一调整。
- 圆角可调整。
- 描边可调整。
- 主要尺寸可调整。
- 动画强度可调整。
- 动画缓动或曲线参数可调整。
- 图标和素材可以独立替换。
- Effects / 插件关键参数在合理范围内可调，不把所有参数暴露成控制项。

### 动画

- 主时序通过 Marker 控制。
- 入场长度可修改。
- 出场长度可修改。
- 元素动画可以独立调整。
- 镜头与元素动画分离。
- 关键运动属性具有合理关键帧。
- 关键帧使用合适的缓入缓出或自定义曲线。
- 动效没有明显线性生硬感。
- 不同元素之间具有合理的节奏、延迟和层次。
- Motion Blur 使用适度。
- 动画曲线与元素材质和功能匹配。

### 后期

- 实拍有独立素材槽。
- 替换素材不会破坏动画。
- 不需要进入大量深层合成才能修改。
- 图标可以替换或重新绑定。
- 外部素材不会因为网络链接失效而丢失。

### 兼容

- AE26 中文版可运行。
- 不依赖中文属性名称。
- 第三方插件只在有明确收益时使用，并记录依赖。
- 字体 / 插件不存在时有容错和降级。
- 外部素材导入失败时有降级方案。
- JSX 具有错误处理和撤销组。
- 未检测到的插件不会被误报为“已安装”。
- AE 脚本不适合自动化的步骤已明确标记为手动处理。

### 验收 / 渲染

- 工程制作、修改或调试完成后，没有未经授权启动完整视频渲染。
- 没有把 `aerender`、AE Render Queue 或 Media Encoder 当成默认收尾步骤。
- 已选择 4–6 个真正具有代表性的关键时间点。
- 至少包含开场、主要动画中间态、Hero Frame、最终状态。
- 关键帧从主合成以原始分辨率输出，默认不降画质。
- 每张关键帧都附有时间码和检查目的。
- 用户未明确授权时，不产生完整时间段的视频文件。
- 用户明确要求最终渲染时，已经说明主合成、时间范围、分辨率、帧率、格式和输出位置。

### AI 再编辑

- 关键元素拥有稳定 AI\_ID。
- 后续脚本不依赖 Layer Index。
- 可以局部 Patch。
- 不会因为修改一个元素重建整个工程。
- AI 能识别图标、素材、动画模块和控制层。
- AI 能读取素材来源和许可证信息。

# 核心标准

以后生成 AE 工程时，应始终把工程理解为：

**视觉成片 + 参数化模板 + 动画系统 + 多类型素材 / AE 原生能力 / 3D / Effects / 插件的合理组合 + 可供 AI 再次操作的数据结构 + 可追溯的素材与依赖系统。**

不是：

**一次性 JSX 把画面画出来，或让 Agent 在 AE 里盲目操作一遍后直接渲染。**

最终要求是：

> 第一次由 AI 创建，之后无论是人工修改还是 AI 修改，都能够快速找到对象、快速调整参数、快速替换内容，并且不破坏已有工程结构。

> 对于难以高质量绘制的图标、产品、人物、机械结构和复杂元素，应优先使用真实素材、官方素材、授权清晰的公开资源、3D 或适合的外部生成资产；能自动获取就获取并导入，无法获取就建立高质量占位并明确告诉用户需要替换什么。所有动效都必须具备符合元素属性和运动逻辑的关键帧、缓动与曲线，而不是只做生硬的起点到终点变化。

> AI 不应被限制为“Shape + Text 生成器”。应根据镜头需要合理调用 AE 原生 Effects、Text Animator、Mask / Matte、Camera / Light、2.5D / 3D、表达式、素材、视频及已安装插件；但所有能力都必须服务于画面和可编辑性，而不是为了炫技而堆叠。

> 默认制作流程必须遵守“需求 / 方案 → 用户确认 → 静帧 → 用户确认 → AE 工程”的阶段门禁。未经用户确认，不得擅自跨阶段推进；遇到会改变创意方向或导致大面积返工的问题必须先问清楚，不能自行脑补。


> 本规范同时适用于 JSX、AEmcp 和混合 Agent 工作流。执行方式可以变化，但工程必须始终保持可理解、可编辑、可局部修改、可追踪。MCP 的价值在于读取真实工程状态并安全地继续工作，而不是绕过工程结构。

> 工程完成不等于渲染授权。默认交付路径是“工程完成 → 4–6 张关键帧 PNG 验收 → 用户在 AE 内自行预览 / 确认 → 用户明确要求后才完整渲染”。未经明确指令，不启动完整时间段的 aerender、Render Queue 或 Media Encoder。
