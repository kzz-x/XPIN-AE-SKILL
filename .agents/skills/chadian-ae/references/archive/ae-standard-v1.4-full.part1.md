# AI 生成 / 修改 After Effects 工程规范 v1.4

适用环境：**Adobe After Effects 26 中文版 / Windows**

适用执行方式：**JSX / ExtendScript、AEmcp / 直接操作 AE 的 Agent，以及 JSX + MCP 混合工作流。**

目标：生成的工程必须同时满足：

**视觉完成度高 + 参数可控 + 动画可调 + 层级清晰 + 中文易读 + AI 可再次修改 + AE26 中文版稳定运行 + 素材来源可靠 + 能合理调用 AE 原生能力 / 外部素材 / 3D / 第三方插件 + 动效节奏自然 + 方案 / 静帧 / 工程分阶段确认 + Agent 可安全地局部修改现有工程 + 默认仅做关键帧静帧验收、不擅自完整渲染。**

---

# 01｜总原则

AE 工程必须按照“可编辑模板”思路制作，而不是生成一堆写死的图层。

禁止：

- 所有颜色写死在 Shape / Text 内。
- 所有元素使用同一种字体、字号、圆角、描边。
- 动画时间全部写死。
- 大量无法理解的表达式。
- 使用 Layer 1、Shape Layer 23、Comp 4 等默认命名。
- 后续修改依赖“第几个图层”。
- 为了方便生成而牺牲 AE 内的可编辑性。
- 为了统一而把所有视觉参数强行做成完全一样。
- 对复杂图标、机械结构或专业符号进行低质量的随意手绘。
- 使用来源不明、授权不清晰或无法追溯的网络素材。
- 制作只有关键帧、没有合理缓动和运动曲线的生硬动效。

应该建立一套**设计 Token + 动画控制 + 工程结构 + 稳定 ID + 素材来源管理**系统。

## AI 能力使用总原则

AI 制作 AE 工程时，**不得默认把任务理解成“用 Shape + Text 把参考图画出来”**。

应先判断这个镜头最适合由什么组成，再选择实现方式。允许并鼓励合理调用：

```text
AE Shape / Text / Solid / Null
真实图片 / PNG / JPG / PSD / AI / SVG
视频 / 实拍 / 序列帧 / 音频
Mask / Track Matte / Blend Mode
Text Animator / Shape Path / Trim Paths
AE 原生 Effects
Expression / Essential Properties
2.5D Layer / Camera / Light / Depth of Field
AE 支持的 3D Model / 外部 3D 渲染素材
已安装且适合项目的第三方插件
必要时由外部工具生成的素材，再导入 AE
```

目标是：**用最适合镜头的能力组合，获得更高视觉完成度，同时保持工程可编辑、可维护。**

禁止为了展示“能力多”而堆叠无意义的 3D、Glow、粒子、插件、Camera 或复杂表达式。

判断标准只有三个：

1. 是否明显提升视觉或制作效率。
2. 是否符合这个镜头的设计逻辑。
3. 是否不会显著降低稳定性、性能和后续可编辑性。

## 实现路线优先级

面对一个视觉元素时，优先选择最合理的来源，而不是机械地全部用 AE 手绘。

推荐判断顺序：

```text
用户已经提供的真实素材 / 品牌官方素材
↓
授权清晰、质量可靠的公开素材 / 开源素材
↓
适合由 AI / 外部工具生成的图片、视频、3D 或纹理素材
↓
AE 原生 Shape / Text / Effects 程序化制作
↓
高质量占位素材槽，等待用户后续替换
```

注意：

- 简单几何、UI、数据图表、路径动画 → 优先 AE 原生制作。
- 产品、人物、工厂、车辆、真实设备、复杂机械结构 → 优先真实素材 / 官方素材 / 3D / 高质量外部素材，不要低质量手绘。
- 需要真正空间关系、透视、景深、Parallax → 再使用 3D Layer / Camera / Light。
- 只需要二维推拉镜头 → 不要为了“高级”强行上 Camera。
- 原生效果能稳定解决 → 不必为了同一效果强行依赖插件。
- 第三方插件能显著提高质量或效率 → 可以使用，但必须遵循插件依赖规范。
- 不要为了等用户回复而停住：素材暂缺时优先继续搭工程、建立占位槽，并在交付时集中列出待替换项。

## Capability Preflight｜正式制作前检查

正式生成 JSX / 修改工程前，AI 应先内部完成一次能力检查：

```text
1. 这个镜头需要哪些真实素材？
2. 哪些可以自己搜索 / 下载 / 生成？
3. 哪些必须由用户提供？
4. 哪些位置需要建立可替换素材槽？
5. 是否需要 AE 原生 Effects？
6. 是否真正需要 3D Layer / Camera / Light / 3D Model？
7. 是否有第三方插件能明显提升效果？
8. 插件是否已经安装 / 能否被脚本调用？
9. 如果素材、字体、插件缺失，降级方案是什么？
10. 哪些步骤属于 AE 脚本 API 不适合稳定自动化的能力，需要用户手动完成？
```

如果缺少必要条件，不要沉默地用低质量替代方案糊弄。

应明确区分：

```text
【已自动完成】
【已使用占位，可后续替换】
【需要用户提供素材】
【建议安装插件】
【需要用户手动完成的 AE 操作】
```


## 执行路径选择｜JSX / AEmcp / Hybrid

本规范是**工程级规范**，不是只针对 JSX。无论最终由脚本生成、AEmcp 直接操作 AE，还是二者混合执行，都必须遵守本规范中的视觉、结构、命名、控制、动画、素材、依赖、可编辑性和验收要求。

正式制作前，Agent 应选择最合适的执行路径：

```text
JSX / ExtendScript
→ 适合批量创建、标准化搭建、重复执行、参数化模块、稳定可复用的工程结构

AEmcp / 直接 AE 操作
→ 适合读取当前已打开工程、理解真实项目状态、局部修改、交互式调试、检查现有层级与结果

Hybrid｜MCP + JSX
→ MCP 负责读取 / 判断 / 定位 / 验证
→ JSX 负责批量或确定性操作
→ MCP 再检查结果并继续局部修正
```

选择标准：

1. 哪条路径更稳定地完成本次任务。
2. 哪条路径更能保留用户已经做过的人工修改。
3. 哪条路径更容易局部 Patch，而不是重建整个工程。
4. 哪条路径更符合 AE 本身的工作方式。
5. 不得为了证明“会用 MCP”或“会写 JSX”而强行选择更复杂的路线。

### AEmcp / 直接操作 AE 的基础原则

当 Agent 可以通过 MCP 直接读取和操作 AE 时：

- 修改前先读取当前 Project、目标 Comp、目标 Layer / Property 的真实状态。
- 不得仅凭提示词假设工程结构、图层顺序、插件状态或当前参数。
- 已存在的主合成、控制层、素材槽、预合成不得无意义重复创建。
- 优先通过 `AI_ID + 合成名 + 图层名 + 类型 / Role` 组合确认目标。
- 能 Patch 就不得重建。
- 修改一个局部问题时，只触碰与该问题相关的对象和属性。
- 用户已经人工调整过、且与本次需求无关的内容应视为需要保护的现状。
- 执行后重新读取目标状态并做结果检查，不能只相信“命令已经成功执行”。

### JSX 与 MCP 的权限边界

工程规范中的以下内容对两种路径都适用：

```text
命名 / Precomp 结构
AI_ID / ROLE / TYPE
控制层 / Design Token
Marker / 动画时序
素材槽 / 替换逻辑
动画曲线 / 缓动
Camera / 3D / Effects / 插件的合理使用
素材来源 / 授权 / 依赖记录
局部 Patch / 保留人工修改
关键帧静帧验收 / 渲染权限
```

只有脚本 API 细节，例如 `matchName`、`try/catch`、`beginUndoGroup()`，才属于 JSX 专属实现规范。

# 02｜强制制作流程与阶段确认

本规范默认采用以下工作流：

```text
用户提出需求
↓
阶段 1｜需求确认 + 设计方案
↓
用户明确确认方案
↓
阶段 2｜生成静帧设计图
↓
用户明确确认静帧
↓
阶段 3｜生成 / 修改 AE 工程
↓
工程结构 / 动画逻辑检查
↓
阶段 4｜关键帧静帧验收
↓
用户确认后，如明确要求才进入完整渲染 / 导出
```

**这是硬门禁。未经用户确认，不得擅自跳过阶段。**

除非用户明确说“直接做工程 / 不用出图 / 跳过方案”，否则必须按照以上流程执行。

## 阶段 0｜需求理解与必要提问

收到需求后，先理解，不要立即生成 JSX、AEP 或静帧。

首先用简洁语言向用户说明：

```text
【我理解的需求】
- 主题 / 文案
- 画面核心内容
- 期望风格
- 时长 / 画幅 / 分辨率 / 帧率（已知时）
- 参考图的作用：严格构图参考 / 视觉风格参考 / 内容参考
- 最终交付：静帧 / JSX / AEP / 素材包 / 其他

【我准备怎么做】
- 主要构图
- 主要动画逻辑
- 计划使用的 AE 能力
- 需要的外部素材 / 3D / 插件

【需要确认的问题】
- 只询问真正会影响设计或工程结果的问题
```

### 必须询问的情况

如果以下信息存在**实质性歧义**，必须先问用户，不能自己乱定：

- 文案、镜头含义或视觉重点存在两种以上明显解释。
- 参考图究竟是“严格还原”还是“只参考风格”不明确。
- 关键产品 / Logo / 人物 / UI 是否必须使用真实官方素材不明确。
- 是否允许改变用户给出的构图、镜头顺序或核心动作不明确。
- 输出比例、时长或分辨率会直接改变构图，但无法从上下文判断。
- 是否允许使用第三方插件，而插件会明显影响最终效果。
- 某一步需要用户已有的专有素材，但 AI 无法可靠替代。
- 一个设计决定会导致后续大面积返工。

提问应一次性集中，优先问 **1–5 个最关键问题**，不要把无关小参数全部丢给用户。

### 不需要反复询问的情况

以下内容在不影响创意方向时，可直接按本规范处理：

- 图层命名。
- Precomp 划分。
- AI_ID。
- matchName。
- 控制层结构。
- 常规 Ease / Graph Editor 处理。
- 通用容错。
- 素材槽结构。
- AE26 中文版兼容细节。

原则：

> **创意方向、事实内容、关键构图、重要素材、重大依赖不能替用户决定；纯工程实现细节可以按规范自主完成。**

### Grill-me / 深度需求澄清不是默认必选

不要把 Grill-me、长问卷或多轮需求审讯变成每个 AE 任务的固定前置步骤。

- 需求清晰、参考明确、影响范围有限 → 直接进入方案阶段。
- 存在多条明显不同的创意路线、重大技术路线差异、成本很高的返工风险或关键条件缺失 → 才适合使用 Grill-me / 深度澄清。
- 即使需要澄清，也优先一次性提出最关键的问题，而不是为了流程完整而增加用户负担。

## 阶段 1｜设计方案

阶段 1 的目标不是立刻制作，而是让用户能够在制作前完整判断方向是否正确。

本阶段**禁止**：

- 直接生成最终 JSX / AEP。
- 未经确认直接开始搭工程。
- 未经确认直接生成最终设计图。
- 因为“感觉这样更好”而修改用户已经明确的核心设定。

本阶段必须输出以下内容。

### A｜需求确认摘要

简洁复述：

```text
主题：
核心文案 / 信息：
画幅：
时长：
视觉参考：
核心动作：
最终需要可修改的内容：
```

如有不确定项，明确标记：

```text
【待确认】
```

不要偷偷补全。

### B｜完整设计方案

至少说明：

- 整体视觉概念。
- 构图结构。
- 主体与信息层级。
- 镜头 / 动画流程。
- 每个主要元素如何运动。
- 哪些部分用真实素材。
- 哪些部分用 Shape / Text / SVG。
- 是否需要 Camera / Light / 3D。
- 是否需要 AE 原生 Effects。
- 是否建议第三方插件。
- 哪些东西需要保持可替换。
- 后续人工最可能修改的位置。

如果是连续口播，可根据内容自然拆分动画段落；但用户没有要求精确秒数时，不要擅自把每句话机械锁死到具体时间码。

### C｜素材 / 插件 /依赖清单

必须在方案阶段就提前说清楚：

```text
【预计自动准备】
- AI 可自行查找 / 下载 / 生成的素材

【建议用户提供】
- 对真实性或版权要求较高、最好由用户提供的素材

【可先占位】
- 暂时缺失但不影响搭建工程的素材

【插件】
- 推荐插件
- 为什么需要
- 是否有 AE 原生降级方案
```

如果预计使用插件，不得等 JSX 做完后才告诉用户。

### D｜完整「生成静帧」Prompt

必须输出一份**可以直接复制给其他生图 AI 使用**的完整 Prompt。

Prompt 至少包含：

- 画幅 / 构图。
- 主体位置。
- 信息层级。
- 视觉风格。
- 材质、灯光、颜色。
- UI / 工业标注 / 字体气质。
- 安全区和留白。
- 真实素材与占位素材的位置。
- 禁止项。
- 参考图应如何继承。
- 不能出现的错误内容。

如果参考图只是风格参考，必须写明：

> 不照抄参考图的具体内容，只继承其视觉语言。

如果参考图是 Canonical Hero Frame，则明确要求尽量还原构图和视觉关系。

### E｜完整「生成 AE 工程」Prompt

必须同时输出一份**可以直接复制给 Work / Codex / 其他 AI 工程代理**的完整 Prompt。

该 Prompt 应引用本规范的核心要求，并根据本次项目明确：

- AE26 中文版。
- 工程尺寸 / FPS / 时长。
- 视觉目标。
- 构图。
- 动画流程。
- 工程层级。
- 控制层。
- Marker。
- 素材槽。
- AI_ID。
- 原生 Effects。
- Camera / Light / 3D（如需要）。
- 外部素材。
- 第三方插件及降级方案。
- 表达式规范。
- 动画曲线。
- 最终检查。
- 验收与渲染权限：默认禁止完整视频渲染；完成后只输出 4–6 张主合成关键帧 PNG；只有用户明确授权后才渲染成片。

该 Prompt 不应只写“按参考图生成”，而应该足以让另一个 AI 在没有上下文的情况下理解任务。

### F｜阶段注意事项

方案结束时必须简洁告诉用户：

```text
需要你确认：
1. 构图是否正确
2. 动画逻辑是否正确
3. 素材 / 插件路线是否接受
4. 有没有需要删掉或增加的元素
```

然后停止。

**用户没有确认前，不进入阶段 2。**

用户可以用自然语言确认，不要求固定口令，例如：

```text
可以
就按这个
方案 OK
继续出图
```

## 阶段 2｜静帧设计图

用户确认阶段 1 后，才进入静帧阶段。

静帧的作用是：

> **先把真正的视觉结果定下来，再反推 AE 工程。**

不得把静帧当成随意灵感图。

### 静帧必须对应已经确认的方案

生成前再次检查：

- 构图是否与方案一致。
- 主体比例是否一致。
- 用户明确要求保留的内容有没有被擅自改变。
- 安全区是否正确。
- 是否存在文字错误。
- 产品 / Logo / UI 是否出现事实错误。
- 是否使用了方案中没有提过的新元素。

除非用户授权重新设计，否则不能因为生图模型“更容易生成”就改变原方案。

### 静帧交付后必须说明

简洁列出：

```text
【这张图确定了】
- 构图
- 色彩
- 材质
- UI / 图形语言
- 主要元素比例

【做成 AE 时】
- 哪些会原生重建
- 哪些会作为外部素材
- 哪些会建立替换槽
- 是否存在插件 / 3D / 字体依赖
```

如果静帧出现 AI 生图无法可靠解决的文字、Logo、数据等，应明确说明：

> 静帧只确定视觉关系，正式 AE 工程中会使用真实文字 / Logo / 数据重建，不沿用生图错误。

然后询问用户是否确认该静帧。

**用户没有确认前，不进入阶段 3。**

如果用户要求修改：

```text
修改静帧
↓
重新确认
↓
仍停留在阶段 2
```

不能一边改图一边偷偷开始做工程。

---

## 阶段 3｜生成 / 修改 AE 工程

只有用户确认静帧后，才开始正式工程制作。

正式制作时，视觉优先级默认是：

```text
1. 用户最后确认的静帧
2. 用户最后确认的设计方案
3. 用户原始文案 / 事实内容
4. 本工程规范
5. AI 自己的实现判断
```

**事实内容永远高于静帧。**

如果静帧里因为 AI 生图出现错字、假 Logo、错误数字、错误产品结构，不得照抄错误。

### 正式制作前最后一次 Preflight

开始生成工程前，向用户简洁说明：

```text
【本次工程将使用】
- AE 原生能力：...
- 外部素材：...
- 3D：...
- 插件：...

【已准备】
...

【仍为占位】
...

【需要你后续提供 / 安装】
...
```

如果此时发现新的**重大问题**，必须停下来问用户。

如果只是非关键工程问题，则按已确认方案和规范自行解决，不要反复打断用户。

### 工程生成原则

正式制作阶段应尽量完整调用真正需要的 AE 能力，而不是退回到纯 Shape + Text：

```text
Footage
Shape
Text Animator
Mask
Track Matte
Effects
Expression
Precomp
Adjustment Layer
Camera
Light
3D Layer / 3D Model
Time Remap
Essential Properties
已确认可用的第三方插件
```

但仍遵循：

> **恰当使用，不为复杂而复杂。**

### 交付时必须同时给出工程说明

最终交付至少包含：

```text
【已完成】
- 工程 / JSX 文件
- 主合成
- 控制系统
- 主要动画

【素材】
- 已导入素材
- 来源 / 授权
- 占位素材
- 待替换素材

【依赖】
- 字体
- 插件
- 3D 模型

【打开工程后常用修改位置】
- 改颜色 → ...
- 改文字 → ...
- 换素材 → ...
- 改动画 → ...
- 改镜头 → ...
```

不要只丢一个 JSX 文件而不解释需要的依赖和后续修改方式。

### 使用 AEmcp 修改现有工程时

如果本次不是“从零创建”，而是通过 MCP 修改用户当前 AE 工程，必须额外遵守：

1. **Read Before Write**：先读取真实工程状态，再决定修改方案。
2. **Patch First**：优先局部修改，禁止为了方便而重建无关模块。
3. **Preserve Manual Work**：保护用户现有人工关键帧、调色、位置、遮罩、素材替换和命名。
4. **Smallest Scope**：一次修改只覆盖完成需求所需的最小对象范围。
5. **Verify After Write**：修改后重新读取 / 检查目标层、关键属性和合成状态。
6. **No Hidden Render**：工程修改完成不等于允许完整渲染；必须进入阶段 4 静帧验收。

---

## 阶段 4｜关键帧静帧验收与渲染权限

工程制作、修改或调试完成后，默认**不得自动渲染完整成片**。

这是一条硬门禁，适用于：

```text
JSX / ExtendScript
AEmcp / 直接 AE Agent
Codex / Work / 其他工程代理
aerender
AE Render Queue
Adobe Media Encoder
任何其他会输出完整时间段视频的方式
```

### 默认禁止自动完整渲染

除非用户明确要求类似以下指令：

```text
“渲染成片”
“导出视频”
“给我最终预览”
或其他明确等价的完整视频输出指令
```

否则：

- 不启动完整时间段的 `aerender` 视频渲染。
- 不自动执行 AE Render Queue 的完整视频输出。
- 不调用 Adobe Media Encoder 输出完整视频。
- 不因为“检查动画”“确认结果”“任务完成”而偷偷后台渲染。
- 不把完整渲染当成每次制作、修改、调试后的默认收尾动作。

用户通常会在 AE 前台自行预览动画，因此 Agent 默认只需要完成**关键帧静帧验收**。

### 关键帧截图要求

完成 AE 工程后，自动选择 **4–6 个最有代表性的时间点**，直接从主合成输出 PNG。

至少包含：

1. **开场状态**：检查初始构图、元素起始状态、是否存在错误露出。
2. **主要动画进行中的关键状态**：检查空间关系、层级、遮挡、动作逻辑。
3. **核心视觉 / Hero Frame**：检查本镜头最重要的视觉完成度。
4. **最终状态**：检查动画结束后的构图、停留状态、元素完整性。

如动画结构复杂，可再选择 1–2 张用于检查重要转场、装配、展开、镜头运动或状态切换。

截图必须：

- 使用主合成原始分辨率。
- 默认不降低画质。
- 输出 PNG 或其他无损静帧格式，优先 PNG。
- 不需要为了截图而渲染整个时间段。
- 时间点应根据动画结构自动选择，而不是机械平均分布。
- 如果某个关键动作发生在很短的区间，应优先截取真正能判断动作逻辑的帧。

### 截图交付说明

截图完成后必须告诉用户：

```text
关键帧 01｜00:00:00:00
检查：开场构图 / 初始状态

关键帧 02｜00:00:02:12
检查：主要动画中间态 / 遮挡 / 空间关系

关键帧 03｜00:00:04:08
检查：Hero Frame / 核心视觉

关键帧 04｜00:00:07:00
检查：最终状态 / 停留构图
```

时间码格式根据工程 FPS 对应。

### 完整渲染的授权边界

只有在用户确认：

- 关键帧视觉没有问题；
- 工程结构没有问题；
- 动画逻辑没有问题；

并进一步明确要求完整视频输出后，才进入最终渲染。

用户明确授权完整渲染后，Agent 在启动前应确认 / 说明：

```text
主合成
渲染时间范围
分辨率
帧率
输出格式 / 编码
输出位置
是否包含音频
```

如果用户只是说“做完”“改好”“给我看看”“检查一下”，默认**不等于完整渲染授权**。

### 禁止静默后台渲染

不得在用户不知情时，把 `aerender`、Render Queue 或 Media Encoder 作为后台完成步骤启动。

如果用户明确要求完整渲染，应让用户知道渲染已经被授权，并把它视为一个独立阶段，而不是工程修改的附带动作。

---

## 修改反馈流程

用户在任意阶段提出修改时，优先修改当前阶段，不擅自推进。

```text
方案阶段修改
→ 更新方案 + 两份 Prompt
→ 等待确认

静帧阶段修改
→ 更新静帧
→ 等待确认

工程阶段修改
→ 优先 Patch 现有工程
→ 保留用户已经做过的人工修改
```

如果修改会推翻已经确认的上游设计，应明确告诉用户：

> 这个修改会影响已确认的构图 / 素材 / 动画逻辑，建议先回到方案或静帧阶段重新确认。

不能默默重做一套新的东西。

---

## 决策权限边界

### AI 可以自主决定

- 图层与合成的工程组织方式。
- 内部命名细节。
- matchName 与脚本实现方式。
- 不改变视觉结果的性能优化。
- 常规关键帧缓动细节。
- 容错与异常处理。
- 用户已经确认方向后的局部技术实现。

### AI 必须征求用户确认

- 改变构图。
- 改变文案或事实内容。
- 改变用户明确指定的动作。
- 更换核心视觉风格。
- 删除主要元素。
- 增加会显著改变画面的主要元素。
- 从 2D 改成 3D 或反之且会明显影响观感。
- 引入重要第三方插件依赖。
- 使用与用户原要求不同的品牌 / 产品 / 人物素材。
- 因实现困难而降低设计目标。

核心原则：

> **技术实现可以自主，创意方向不能越权。**

> **遇到真正影响结果的问题就问；没有问题时不要为了“走流程”制造无意义问题。**

> **任何阶段都要让用户知道：现在做到哪一步、下一步是什么、有哪些依赖或风险。**
