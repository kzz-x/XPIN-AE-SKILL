# 工程｜人机共用 AE / PR 模板库规范

用于把成熟 AE / Premiere 资产整理成长期可复用的“视觉系统包”，同时服务真人设计师与 AI Agent。

> 核心目标：人第一次拿到就知道怎么用；AI 第一次读取就知道入口、依赖、可改范围和禁区；正式母版永不被生产任务直接修改。

---

## 1｜最高级原则

### 1.1 视觉系统包是最高层级单位
模板库的主要单位不是单个 AEP，而是“视觉系统包｜Style Pack”。

一个视觉系统包代表统一的：
- 视觉语言；
- 构图逻辑；
- 色彩 / 字体 / 材质；
- Motion 规律；
- 功能组件；
- 常用场景；
- 公共素材与依赖。

例如：`iOS Core 视觉系统`、`复古侦探信息系统`。

### 1.2 完整套装是唯一设计母体
每个视觉系统包内部包含：
- **完整套装｜Full Kit**：唯一设计母体；
- **场景模板｜Scene**：多个组件组合好的成熟镜头；
- **独立组件｜Component**：可独立搜索、预览、复制和使用的视觉积木；
- **公共素材｜Assets**；
- **依赖环境｜Dependencies**；
- **预览 / 参考 / 模板信息**。

场景和独立组件都从完整套装派生。不要让“完整套装里的组件”和“独立组件 AEP”长期分别演化。

### 1.3 正式发布版不可变
正式发布版只允许：
- 查看；
- 搜索；
- 预览；
- 复制。

禁止：
- 原地改；
- 原地保存覆盖；
- 删除 / 重命名正式母版；
- AI 直接对正式母版执行写操作。

使用模板必须先复制到工作区；修改模板本身必须从正式版派生开发草稿，再发布新版本。

## 2｜源工程隔离门禁｜Source Isolation Gate

这是模板化任务的 P0 安全规则，优先级高于“整理方便”。

当用户说“做成模板 / 模板化 / 整理成模板 / 拆组件 / 沉淀模板库 / 做成视觉系统包”等：

1. **先识别源 AEP、源素材目录和用户当前工作工程。**
2. 源 AEP / 源文件夹默认视为只读参考，不在原位置整理。
3. 在任何结构性写入前，必须建立可靠恢复点。
4. 另外创建**独立模板化工作副本**；所有重命名、归档、删层、Relink、依赖收集、拆组件、控制器整理都只发生在副本。
5. 不改变用户原 AEP 路径，不把备份或模板化副本切成用户原工作工程的替代品。
6. 不删除、移动、覆盖用户原素材。
7. 若工具不能可靠完成复制 / 备份，要明确停止破坏性步骤并提醒用户，而不是假装已经保护。
8. 正式发布前再次确认：源工程、源素材、模板化副本三者路径可区分。

推荐语义：
`源工程（只读） → 模板化工作副本（可改） → 待审核版 → 正式发布版（只读）`

## 4｜AEP 内部结构

模板型 AEP 推荐：

```text
00_开始这里
01_主输出
02_编辑区
03_替换槽位
04_功能模块
05_素材
90_参考
99_核心
```

### 4.1 主输出与编辑区分离
`主输出`负责最终画幅、帧率、时长、最终处理与输出。
`编辑区`负责构图、内容、组件组合、动画与参数。

### 4.2 控制层跟合成走
**不要在项目面板单独建立“控制层文件夹”作为主要控制入口。**

每个主要可编辑合成：
- 时间线最上方放一个控制 Null；
- 主编辑合成可命名 `CTRL_全局控制`；
- 子模块合成可命名 `CTRL_控制器`；
- 用户可见命名中文优先，技术缩写只作为辅助。

控制器只暴露高频参数：颜色、间距、尺寸、常用位置、动画速度 / 幅度、材质强度、必要开关等。不要为了参数化暴露大量低价值内部参数。

### 4.3 替换槽位｜SLOT
高频替换内容尽量槽位化，例如：
- `SLOT_产品图`
- `SLOT_人物`
- `SLOT_截图01`
- `SLOT_视频01`
- `SLOT_Logo`

外部动画优先引用槽位，而不是直接引用真实素材。槽位应明确素材类型、比例、适配、锚点、安全范围和是否允许裁切。

### 4.4 功能模块｜Module
只有能独立承担明确视觉功能的结构才升级为模块。模块应：
- 功能明确；
- 自己拥有控制器；
- 尽量自洽；
- 尽量少依赖其他独立组件。

### 4.5 核心｜Core
布局计算、路径系统、Rig、材质底层、表达式驱动等放入核心区域。
正常使用时默认锁定 / 不主动修改。只有用户明确修改模板本身时才进入。

## 5｜独立组件拆分原则

一个内容值得拆成独立组件，至少应满足：
- 可独立搜索；
- 可独立预览；
- 可独立复制；
- 可独立使用；
- 有明确复用价值。

不要把每个小图层拆成独立 AEP。

### 5.1 依赖方向
优先：
`场景模板 → 多个独立组件`

避免：
`组件 A → 组件 B → 组件 C`

独立组件尽量自包含。

### 5.2 素材策略
完整套装开发阶段可以共享公共素材。
独立组件发行时，应尽量带齐自身运行必需的素材与内部预合成，避免复制出去后立刻脱机。

## 6｜依赖环境与脱机检查

模板必须主动识别所有换机 / 脱机风险，包括但不限于：
- AE / PR 第三方插件；
- 字体与特殊字重；
- JSX / JSXBIN 脚本；
- FFX 预设；
- CEP / UXP 面板；
- LUT / ICC / OCIO；
- 特殊 Codec；
- 第三方渲染器；
- 三维模型 / HDRI / 材质贴图；
- 图片 / 视频 / 音频 / 序列帧；
- JSON / CSV / 外部数据；
- 外部表达式资源；
- Dynamic Link / Media Encoder；
- 特定 AE / PR 版本；
- GPU / CUDA 或其他特殊运行环境。

### 6.1 依赖分发
**可合法分发**：可以随包提供安装包 / 资源。
**不可合法分发**：只记录名称、版本、官方获取方式、安装说明、是否必须、缺失影响、可选替代方案。禁止把商业插件、字体、素材非法打包。

### 6.2 AI 自主依赖收集｜默认方式

模板化任务默认**不用 AE 原生“收集文件”**，改用 AI 自主依赖收集：

`工程真实引用 → 文件系统复制 → 环境依赖补全 → 外部路径残留检查`

原因：
- 不依赖 AE 收集文件 GUI；
- 可以只收当前模板真实需要的依赖；
- 除 Footage 外还能覆盖字体、插件、脚本、LUT、3D、HDRI、贴图等；
- 更容易生成可读依赖清单并判断哪些能打包、哪些只能记录。

#### 工程引用收集
通过 AE / MCP / JSX 读取模板副本真实引用路径，然后把需要的文件**复制**到模板包内部。只处理当前模板 / 当前资产根必要依赖，不默认扫描整个 Project 或整个磁盘。

#### 环境依赖补全
主动检查字体、插件、`.aex`、脚本、预设、CEP / UXP、Codec、3D Renderer、Adobe 版本、Dynamic Link、Media Encoder、GPU 等换机风险。

#### 复制边界
- **自动复制**：真实引用媒体、数据、模型、HDRI、贴图、自制脚本 / 预设，以及许可允许的字体与真正自包含的单文件 `.aex`。
- **检查后复制**：字体、`.aex`、CEP / UXP、第三方脚本；先确认伴随 DLL / 资源目录 / 安装器 / 授权依赖。
- **仅记录**：Red Giant / Maxon、Sapphire 等大型授权插件，Adobe 自带组件，或许可 / 自包含性不明确的商业依赖。

依赖收集永远遵守：
**只复制，不移动，不删除，不覆盖原件；只收最小必要集合。**

收集完成后必须检查模板副本是否还残留对原素材目录、NAS、桌面 / 下载目录、原插件目录等外部路径的依赖。

### 6.3 使用前检查
人和 AI 使用模板前都要检查：
`软件版本 → 字体 → 插件 → 脚本 → 素材 → LUT / Codec / 其他环境`

状态可标记：
- **可正常使用｜READY**
- **可降级使用｜DEGRADED**
- **无法正常使用｜BLOCKED**

若缺失关键依赖，AI 禁止偷偷删效果、换插件、换字体或重新设计。先说明缺什么、影响什么、如何安装、有没有降级方案，再按用户决定执行。

## 7｜动画与时间结构

模板既服务真人 Motion Designer，也服务 AI。

- 主 Timing、Hero Motion、Camera、重要路径、重要排版动画：优先真实关键帧，保留 Graph Editor 精调能力。
- wiggle、loop、持续扰动、自动跟随、距离驱动、重复、自动连接等规律行为：优先 Expression / Rig。
- 核心原则：**视觉节奏用关键帧；机械规律和持续规律优先表达式。**

成熟组件尽量有：
- `入场｜IN`
- `主体 / 停留｜HOLD`
- `出场｜OUT`

优先使用 Marker 标记阶段，便于之后根据口播、剪辑点和镜头长度重排。不要默认用整体 Time Stretch 粗暴解决所有时长变化。

## 8｜可编辑等级

可按资产声明：
- **L1｜内容替换**：图片、视频、文字、Logo；
- **L2｜样式调整**：颜色、字体、阴影、材质；
- **L3｜布局调整**：位置、尺寸、间距、排列；
- **L4｜动画调整**：Timing、曲线、速度、幅度；
- **L5｜结构重构**：表达式系统、Rig、Camera、模块架构。

AI 默认不要超过模板声明的安全等级。

正常修改优先级：
`SLOT → CTRL → 编辑区允许项 → 功能模块 → 核心`

## 9｜预览、自解释与中文优先

视觉系统包至少提供整体封面与整体预览；场景和独立组件尽量有自己的预览。

### 9.1 模板任务允许自动生成轻量预览视频
模板化 / 视觉系统包任务属于“预览视频例外”：AI 可以自动为模板生成短预览视频，不需要把它当成“完整成片渲染”再次向用户申请。

但预览必须以**低成本、快速判断模板内容**为目标，禁止为了预览占用大量制作 / 渲染成本。

默认规则：
- **只截代表性时间段**，不要为了预览把长合成从头到尾全部渲染；
- 独立组件优先约 **2–5 秒**；
- 场景模板优先约 **3–8 秒**；
- 完整套装整体预览优先约 **5–10 秒**，只展示代表性内容，不要求覆盖全部组件；
- 默认使用 **720p 或等价低成本预览尺寸**，不为模板预览输出 4K / 高码率母版；
- 默认单次编码、普通 H.264 / 等价轻量格式即可；不做多轮高质量重渲染；
- 已有可用预览时优先复用，不重复渲染；
- 同一批次只为本次新增 / 修改且确实需要判断 Motion 的内容生成预览，不机械重渲染整个视觉系统；
- 如果某效果 / 插件 / 3D 导致预览明显昂贵，优先缩短片段、降低预览分辨率，必要时退回代表性静帧；**不要让预览阻塞模板整理本身**。

预览是检索和理解资产的辅助物，不是最终交付片。

AEP 即使脱离外部说明文件也应能解释自己：
`00_开始这里` 中至少写明：
- 这是什么；
- 当前版本；
- 从哪个编辑合成开始；
- 替换槽位在哪里；
- 控制器位于每个合成时间线顶部；
- 主输出在哪里；
- 关键依赖；
- 哪些区域不要修改。

所有人类可见内容默认中文优先。必要英文写成“中文｜English”，机器接口保持原值。

## 10｜版本与生命周期

建议语义版本：
- `1.0.1`：修订 / Bug；
- `1.1.0`：新增兼容能力；
- `2.0.0`：结构或接口明显变化。

已复制进生产项目的模板是快照，不自动跟随模板库升级。

生命周期：
`待整理 → 开发中 → 待审核 → 正式发布 → 停止推荐 → 归档`

正式发布版不可覆盖。

## 11｜正式发布前检查

至少确认：
- 源工程与源素材仍完整，未被模板化任务改写；
- 模板化副本有独立路径；
- 完整套装可正常打开；
- 独立组件可独立打开；
- 场景模板正常；
- 无新增 Missing Footage；
- 字体 / 插件 / 外部依赖明确；
- 每个主要可编辑合成顶部有自己的控制 Null；
- SLOT / 模块 / 核心边界清楚；
- 预览与快速开始存在；
- 版本明确；
- 关键输出正常；
- 换机时知道如何恢复依赖。

建议做一次真人或独立 Agent 盲测：只给模板包，不口头解释，看是否能找到组件、复制到工作区、替换内容、调参数并输出。

## 12｜AI 模板化任务标准流程

当用户要求“做成模板 / 模板化 / 整理成模板 / 拆成组件 / 沉淀模板库”等：

```text
识别源工程与源素材
↓
Recovery Point Gate
↓
Source Isolation Gate：复制到独立模板化工作副本
↓
只分析目标资产根合成与必要依赖
↓
保持已确认视觉和 Motion，不借模板化重新设计
↓
整理完整套装结构
↓
把控制层放到各自合成时间线顶部
↓
建立 SLOT / MODULE / CORE 边界
↓
盘点所有脱机依赖
↓
筛选真正值得拆的独立组件
↓
从完整套装派生独立组件与场景
↓
补预览 / 快速说明 / 依赖说明 / 版本信息
↓
验证
↓
待用户审核
↓
发布为新的只读正式版本
```

除非用户明确要求，不要一次处理整个历史模板库。一次优先完成一个视觉系统包或一个明确资产根。

## 13｜与普通老工程整理的关系

如果用户只说：
“整理这个工程、让它好改、把控制参数整理一下”
→ 使用 `recipes/refactor-existing-asset.md`。

如果用户明确要：
“做成模板、做成模板库资产、拆独立组件、形成视觉系统包”
→ 使用 `recipes/templateize-style-pack.md` 并加载本文。

模板化任务可以复用老工程整理规则，但必须额外遵守：
- 源工程隔离；
- 完整套装唯一母体；
- 场景 / 组件派生；
- 依赖环境包；
- 预览与说明；
- 版本 / 生命周期；
- 正式发布版不可变。
